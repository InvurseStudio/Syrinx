What failed or looked odd

  1. Gemma 4 E2B as shipped read the ~3K prompt at 15,315 tokens/s in the main run, against 18,012 with drafting off. It is the third run in a row where this happens to the first server of the run (12,767 after PR 169, 13,927 that afternoon). Re-run alone afterwards, both settings, short, medium, short, medium (recheck-e2b-medium.jsonl): 18,018 every time. Something about the first server after the vireo-cli speed check, not the draft model; the page keeps the main run's numbers.
  2. Gemma 4 E4B's small prompt read at 1,675 tokens/s as shipped against 2,267 after PR 169 (−26%); it is 67 tokens in ~40 ms, the same as drafting off read the time before, so noise at that size.
  3. llama.cpp, unchanged, landed within 3.7% of the after-PR-169 run on every medium, large and xlarge number (median 1.5%). Its small-prompt first tokens moved up to +60% (59 → 37 ms on Gemma 4 E2B): times that small are not comparable run to run.
  4. Nothing errored, and no row spilled.
